# T3-native work

Follow live T3 tool guidance when it differs from a stored playbook. Tool names may have an MCP prefix.

- Discover current targets with orchestrator_capabilities and honor session choices. For T3-owned child work use delegate_task with task, paths, acceptance, ownership, and verification. Children receive only their brief. Follow live guidance for same-provider native delegation and model support.
- Retain taskId; use task_status or task_cancel. Each later review round is a fresh delegate_task containing prior findings and objections, with a distinct clientRequestId stable across retries. Do not dispatch through childThreadId.
- Keep children attached to this thread. Create ordinary top-level threads only when the user explicitly requests separate/new conversations. Give code writers separate worktrees or nonoverlapping ownership; the parent integrates and updates shared task status.
- Register every PR created or worked on with link_pull_request, including every layer of a stack. Check list_thread_pull_requests before handoff.
- When asked to monitor, use watch_pull_request and end the turn for the app's wake-up. Use unwatch_pull_request on handback. Do not substitute a shell polling loop.
- For browser work start with preview_status, then preview_open if needed, and use native preview tools and snapshot locators. Preserve observed verification artifacts.
- Reconstruct prior work with bounded thread search/read; revalidate the issue, checkout, head SHA, and checks. Save only missing resume information.
- Use schedule_task only for requested recurring work, with a structured schedule. Cursor Cloud Automations are a separate scheduler/runtime.
